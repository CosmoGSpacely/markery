# Session Protocol

How to open and close a historian session in the Markery workflow.

---

## Opening a session

**1. Read BRIEF.md first.**

Before doing anything else, read `projects/<project>/BRIEF.md`. This file is generated by `markery historian prepare <project>` and reflects the current state of the research: confirmed pairs, content gaps, available signals, candidate highlights, and the session recommendation.

If BRIEF.md does not exist or has not been generated recently (check the `prepared:` timestamp in the YAML frontmatter), ask the researcher to run the prepare command before continuing:

```
markery historian prepare <project>
```

**2. Read OBJECTIVES.md.**

`projects/<project>/OBJECTIVES.md` contains the project thesis, scope boundaries, and content priorities. This is the stable document — it does not change between sessions unless the project direction changes. Read it once and carry it forward.

**3. Confirm the session task.**

BRIEF.md ends with a session recommendation derived from the highest-priority content gap. Confirm this with the researcher before starting work:

> "BRIEF.md suggests working on [X] this session. Does that match your priorities, or would you like to focus on something else?"

If the researcher redirects, note the new focus and proceed.

**4. State scope boundaries before writing.**

Before producing any site content, confirm:
- Which project is active
- Which content type you are producing (match essay, entity summary, thematic essay, etc.)
- Whether any confirmed pairs or entities are out of scope for this session

---

## During a session

**Emit operation requests when data is missing.**

If a confirmed pair lacks signal fields (abstract text, goods description) that would strengthen the essay, emit a structured operation request (see `interface.md` — Operations section) rather than proceeding silently with incomplete data. The researcher will run the requested command and provide the results.

Do not block essay writing on unfetched data. Write with what is available and note what is missing:

> "The patent abstract for US2152606A is not in the current dataset. The correspondence analysis below is based on patent title and CPC classes only. Run `markery patent signals information-systems` to fetch abstract text, then revisit the correspondence section."

**Reference available signals explicitly.**

When BRIEF.md lists patents in `signals_available`, those abstracts are in the database and can be queried. When BRIEF.md lists `figures_available`, figure descriptions can be grounded in what the figure shows. Use these to improve essay depth — do not treat them as optional.

**Keep scope visible.**

If a research thread leads outside the project's date range, technology scope, or entity set, name the boundary explicitly:

> "This would take us beyond the 1939 scope boundary. Do you want to note it for Phase 6D extension, or pursue it now?"

---

## Closing a session

**1. State what was produced.**

At session end, summarize:
- Which content files were written or updated
- Which content gaps were resolved (or partially resolved)

**2. Identify unresolved operation requests.**

If you emitted any operation requests that the researcher did not yet run, list them explicitly so they can be run before the next session:

> "Before the next session, run:
> - `markery patent signals information-systems` — to fetch abstracts for US2152606A and US2178457A
> - `markery historian prepare information-systems` — to regenerate BRIEF.md with updated gaps"

**3. Do not summarize what the researcher already knows.**

The researcher was present for the session. Do not recap the historical content or repeat the essay. Summarize only the workflow state: what changed, what is pending, what should happen next.

---

## Session startup checklist

| Step | Action | Check |
|---|---|---|
| 1 | Read BRIEF.md | `prepared:` timestamp is recent |
| 2 | Read OBJECTIVES.md | Thesis and scope clear |
| 3 | Confirm session task | Researcher agrees on focus |
| 4 | Check signals_available | Know what data is ready |
| 5 | Begin content production | Start with highest-priority gap |
